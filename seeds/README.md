# Демо-сиды

Наполняют стенд правдоподобными данными: посты новостей, отзывы на игры, скидки,
обложки игр, просмотры/реакции постов и комментарии. Запуск одной командой при
поднятом стеке:

```bash
docker compose --profile demo run --rm demo-seeder
```

Сервис `demo-seeder` (профиль `demo`, в обычный `up` не входит) монтирует эту папку
и uploads-том, прогоняет скрипты через `mongosh` на праймари (mongo3) — см.
`run-all.sh`.

## Принципы

- **Демо — это данные, а не ветки кода.** В боевом коде нет «демо-режимов»;
  обложки игр — обычные файлы в `/uploads/demo-covers/`, которые отдаёт та же
  статика, что и загруженные через админку аватары. Переход на настоящий контент —
  замена данных, код не трогается.
- **Идемпотентность.** Повторный запуск безопасен: свои прошлые данные скрипты
  находят по маркерам (`seed-` в `userId`/`anonId`/`viewerKey`, слаги постов)
  и пересоздают. Настоящие действия пользователей не затрагиваются.
  **Исключение — `seed-discounts.js`**: у скидок нет поля-маркера, поэтому он
  пересоздаёт коллекцию GameDiscounts целиком. На стенде это ок; на окружении
  с настоящими скидками его из списка нужно убрать.
- **Детерминизм.** Псевдослучайность считается от слагов: повторный прогон даёт
  те же цифры и картинки, демо не «плывёт» между перезапусками.

## Скрипты

| Скрипт | Что сеет |
|---|---|
| `seed-news.js` | 6 постов блога с версиями и контентом |
| `seed-reviews.js` | ~67 отзывов на игры (Published + немного Hidden) |
| `seed-discounts.js` | скидки ~на четверть каталога, 15–85%, пара «скоро закончится» |
| `seed-game-covers.js` | SVG-обложки всех игр в uploads-том + `imagePath` |
| `seed-engagement.js` | уникальные просмотры, реакции и дочитывания постов |
| `seed-comments.js` | комментарии под постами (написаны под содержание) |

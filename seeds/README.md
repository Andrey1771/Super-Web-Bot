# Демо-сиды

Наполняют локальный стенд правдоподобными данными: посты блога, отзывы, скидки, обложки,
демо-ПО, закупочные цены ключей, заказы, вовлечённость, комментарии и команду на «О нас».
Запуск одной командой при поднятом стеке:

```bash
docker compose --profile demo run --rm -e ALLOW_DEMO_SEED=1 demo-seeder
docker compose restart backend
```

Сервис `demo-seeder` (профиль `demo`, в обычный `up` не входит) монтирует эту папку
и uploads-том и прогоняет скрипты через `mongosh` по строке реплика-сета — см. `run-all.sh`.
Перезапуск backend нужен из-за команды на «О нас»: настройки сайта он держит в памяти.

## Только для стенда

Сиды пишут выдуманные данные, а `seed-discounts.js` стирает все скидки. На боевой базе это
порча данных, поэтому без флага `ALLOW_DEMO_SEED=1` откажется работать и `run-all.sh`, и каждый
скрипт по отдельности. Флаг намеренно не прописан в `docker-compose.yml`: его передают руками
при каждом запуске.

## Удаление демо-данных

`remove-demo.js` убирает всё, что записали сиды, по их меткам: выдуманные товары (витринная игра,
апкаминги, демо-ПО) со всеми ссылками на них, ключи `TALE-`/`demo-cost-`, заказы `DEMO-`, отзывы,
комментарии и просмотры от `seed-*`, демо-посты, скидки и команду «О нас». Настоящие игры с теми же
названиями остаются — их карточки заполняет импорт из Steam (админка → Steam import). Ключи,
выданные по настоящим заказам, тоже остаются.

```bash
docker compose exec -T mongo1 mongosh --quiet "mongodb://mongo1:27017,mongo2:27017,mongo3:27017/SteamShopDatabase?replicaSet=rs0" \
  --eval "const ALLOW_DEMO_CLEANUP=1" --file /dev/stdin < seeds/remove-demo.js
docker compose exec backend sh -c 'cd /app/wwwroot/uploads && rm -rf demo-covers demo-upcoming demo-media demo-team demo-reviews'
```

Перед запуском — резервная копия. На стенде это сделано 2026-10-01.

## Принципы

- **Демо — это данные, а не ветки кода.** В боевом коде нет «демо-режимов»;
  обложки игр и фото команды — обычные файлы в `/uploads/demo-covers/` и `/uploads/demo-team/`,
  которые отдаёт та же статика, что и загрузки через админку. Переход на настоящий контент —
  замена данных, код не трогается.
- **Идемпотентность.** Повторный запуск безопасен: свои прошлые данные скрипты
  находят по маркерам (`seed-` в `userId`/`anonId`/`viewerKey`, слаги постов)
  и пересоздают. Настоящие действия пользователей не затрагиваются.
  **Исключения:** `seed-discounts.js` пересоздаёт коллекцию GameDiscounts целиком — у скидок
  нет поля-маркера; `seed-team.js` заменяет список команды целиком.
- **Детерминизм.** Псевдослучайность считается от слагов: повторный прогон даёт
  те же цифры и картинки, демо не «плывёт» между перезапусками.

## Скрипты

В порядке запуска из `run-all.sh`:

| Скрипт | Что сеет |
|---|---|
| `seed-showcase-game.js` | витринная игра Lanternfall: галерея, раздельные студии, 12 ключей |
| `seed-news.js` | 6 постов блога с версиями и контентом |
| `seed-reviews.js` | отзывы на игры по слагам, все состояния витрины: Very Positive/Mixed/Negative, один отзыв, больше страницы, на модерации, скрытые; свои прошлые пересоздаёт |
| `seed-discounts.js` | скидки ~на четверть каталога, 15–85%, пара «скоро закончится»; **стирает прежние скидки** |
| `seed-game-covers.js` | SVG-обложки всех игр в uploads-томе + `imagePath` |
| `seed-software.js` | 6 вымышленных программ: лицензии «срок × устройства», подписка, активация, ключи по лицензиям |
| `seed-key-costs.js` | выдуманная закупочная цена для ключей без неё — чтобы отчёты о прибыли не показывали нули |
| `seed-orders.js` | оплаченные демо-заказы на настоящие игры каталога, ещё без ключей |
| `seed-upcoming-games.js` | 6 вымышленных игр с датами релиза впереди (полка «Upcoming games», фильтр «Coming soon»); без ключей |
| `seed-engagement.js` | уникальные просмотры, реакции и дочитывания постов |
| `seed-comments.js` | комментарии под постами (написаны под содержание) |
| `seed-team.js` | команда на «О нас»: 4 вымышленных человека с ролями, описаниями и фото |

Любой скрипт можно запустить отдельно:

```bash
docker compose --profile demo run --rm -e ALLOW_DEMO_SEED=1 --entrypoint mongosh demo-seeder \
  --quiet "mongodb://mongo1:27017,mongo2:27017,mongo3:27017/SteamShopDatabase?replicaSet=rs0" \
  /seeds/seed-team.js
```

Из Git Bash на Windows перед командой нужен `MSYS_NO_PATHCONV=1`, иначе путь `/seeds/...`
превратится в путь Windows и mongosh не найдёт файл.

## Демо-ПО

`seed-software.js` наполняет софт-режим каталога (`/games?type=software`, товар — `/games/{slug}`).
Без ПО в каталоге пункт Software в шапке, плитки категорий и полка «Software deals» не показываются.
Названия, вендоры и ссылки вымышленные (домены `.example`). Покрывает сетку лицензий с дырами,
подписку, бессрочные лицензии, товар с одной лицензией, свою скидку у лицензии, лицензию без ключей
и лицензию с малым остатком. Идёт после `seed-game-covers`: тот переписывает `imagePath` всем товарам.

## Команда на «О нас»

`seed-team.js` записывает ту же команду, что заведена на стенде через админку: имена, роли,
подписи, описания и фотографии. Фото лежат в `assets/team/*.webp` и копируются в uploads-том,
адреса пишутся от корня сайта (`/uploads/demo-team/mara.webp`) — так они работают на любом стенде.

Люди вымышленные. Раздел «Meet the team» на боевом сайте — утверждение о живых людях, поэтому
перед запуском его заменяют на настоящую команду или очищают (см. `docs/pre-launch.md`).
Правится команда в админке: Settings → Meet the team.

## Будущие игры

`seed-upcoming-games.js` заводит шесть вымышленных игр с датами релиза впереди: от трёх недель
до полугода от дня запуска. Даты считаются от текущего дня, а не зашиты — зашитые через полгода
стали бы прошлым, и игры «вышли» бы без ключей. Всё остальное детерминировано: id от слагов,
обложки (`/uploads/demo-upcoming/*.svg`, своя папка, чтобы `seed-game-covers` их не переписал),
тексты. Ключей нет намеренно: для «Coming soon» витрина показывает дату и «Wishlist».
Идёт после отзывов, скидок и заказов — у невышедших игр их не бывает; `seed-reviews` дополнительно
пропускает игры с датой в будущем.

## Витринная игра

`seed-showcase-game.js` заводит `lanternfall` — обычную с виду карточку каталога,
которая закрывает две дыры в демо-данных. Идёт первой в `run-all.sh`, чтобы попасть
в выборку `seed-reviews` и `seed-discounts` и получить отзывы, рейтинг и, возможно, скидку.

Что она покрывает — две ветки фронта, которые на остальном каталоге не выполняются:

- **Раздельные студии.** У всех 50 игр `developer.name === publisher.name`, поэтому
  карточка всегда схлопывается в одну строку «Developer & publisher». Здесь студии разные
  (Emberline Studio / Northlight Games) — блок показывает две строки.
- **Сортировка галереи.** Ни у одной игры каталога нет ни одного элемента галереи.
  Здесь их восемь: 3 видео (2 помечены трейлерами) и 5 кадров в пропорциях 16:9, 21:9,
  4:3 и портрет. В базе они лежат в перемешанном порядке — `orderMedia()` на фронте
  должен выдать трейлеры первыми, дальше остальное по `order`. Ожидаемую
  последовательность скрипт печатает при запуске.

Помимо этого игра заведена так, чтобы её реально можно было купить: `_id` в `Games` и
`GameDetails` — ObjectId (со строковым чекаут падает на «Some items are no longer available»,
потому что `GameDb.Id` помечен `[BsonRepresentation(BsonType.ObjectId)]`), и на складе лежат
12 непроданных ключей в том же формате, что у остальных игр.

Кадры галереи скрипт рисует сам (детерминированные SVG-сцены), видео лежат
в `assets/` — см. `assets/README.md`.

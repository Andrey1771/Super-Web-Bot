# Перед запуском

Что проверить, прежде чем открывать магазин покупателям. Установка сервера — [deploy.md](deploy.md).

## Блокеры: без этого запускать нельзя

### Данные

- [ ] **База продакшена — новая, пустая.** Не переносите на сервер дамп стенда: там тестовые
  заказы, отзывы и пользователи. Каталог на сервере собирается тем же импортом из Steam, что и на
  стенде (deploy.md → «Каталог и новости»), новости — `deploy/import-news.sh`.
- [ ] Если демо-сиды всё же запускались на этой базе — `seeds/remove-demo.js` (см. seeds/README.md).
- [ ] **Цены.** Импорт ставит розничную цену Steam в долларах — это потолок, а не цена магазина.
  Пересчитайте от закупки (Admin → карточка игры → Pricing) до открытия продаж.
- [ ] **Ключи.** Без ключей все игры показываются «Нет в наличии» и купить их нельзя. Загрузите
  ключи от поставщика (Admin → Product keys) — и уточните у него право использовать материалы игр
  (описания, скриншоты, трейлеры из Steam): обычно оно идёт вместе с договором на ключи.
- [ ] **Команда на «О нас»** — настоящие люди или пустой раздел (Admin → Settings → Meet the team).
  Вымышленные лица на боевом сайте — утверждение о живых людях.
- [ ] `ABOUT_FOUNDED_YEAR` — настоящий год или пусто.

### Юридическое

- [ ] **Реквизиты продавца.** В `appsettings.json` (секция `Legal`) — вымышленная компания, и
  `Draft` стоит `false`: витрина показывает её как настоящую. Задайте свои через `Legal__*` в
  `docker-compose.yml` (там есть закомментированный шаблон), а пока текст не вычитал юрист —
  `Legal__Draft=true`.
- [ ] Условия, политика конфиденциальности, возвраты — прочитаны юристом для вашей страны.

### Деньги

- [ ] Stripe в live-режиме: `STRIPE_SECRET_KEY=sk_live_…`, `STRIPE_PUBLISHABLE_KEY=pk_live_…`.
- [ ] Вебхук в Stripe Dashboard → Developers → Webhooks: `{PUBLIC_URL}/api/payments/webhook`,
  события `payment_intent.succeeded`, `charge.refunded`, `charge.dispute.created`,
  `charge.dispute.updated`, `charge.dispute.closed`. Его секрет — в `STRIPE_WEBHOOK_SECRET`.
  Без вебхука оплаченные заказы не получат ключи.
- [ ] Stripe Tax включён и настроен на live-аккаунте (регистрации в странах продаж).
- [ ] Пробная покупка настоящей картой на маленькую сумму и возврат через админку.

### Доступы

- [ ] `TALESHOP_ADMIN_PASSWORD` — длинный случайный (продакшен без него не запустится, но
  `admin` формально тоже подходит). После первого входа — включить 2FA (Account → Security).
- [ ] Временный администратор Keycloak заменён постоянным (см. deploy.md → «Админ-консоль Keycloak»).
- [ ] `https://<домен>/auth/admin/` отвечает 404.
- [ ] `.env` на сервере — `chmod 600`, его копия хранится вне сервера.

### Почта

- [ ] SMTP настоящего сервиса (`SMTP_*`, `MAIL_FROM`). Без него не уйдут ключи гостям, письма
  восстановления и подтверждения адреса.
- [ ] Домен отправителя: SPF, DKIM и DMARC в DNS — иначе письма уходят в спам.
- [ ] Проверено вживую: «Забыли пароль» в Keycloak, письмо с ключом после покупки, подтверждение
  почты гостя.

### Резервные копии

- [ ] Через сутки после запуска в `backups/` есть файлы всех трёх видов.
- [ ] Копия вне сервера настроена ([backup-restore.md](backup-restore.md)).
- [ ] Восстановление хотя бы раз проверено.

## Важно, но можно сразу после запуска

- [ ] **Telegram-бот:** `BOT_TOKEN`, `BOT_WEBHOOK_SECRET`; `BOT_WEBHOOK_URL` пустой (вебхук —
  `{PUBLIC_URL}/api/Telegram`). На стенде в `.env` стоит адрес старого ngrok-туннеля — на сервер
  его не переносить. `TELEGRAM_ADMIN_USERNAME` / `TELEGRAM_ADMIN_CHAT_ID` — куда слать уведомления.
- [ ] **Чат поддержки:** `DEEPSEEK_API_KEY` и `SUPPORT_CHAT_DAILY_BUDGET_USD` (по умолчанию $5 в
  сутки). Ollama на сервере нет — без ключа ассистент недоступен.
- [ ] **Turnstile:** настоящие ключи для домена (`TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET_KEY`).
  Тестовые ключи стенда пропускают всех.
- [ ] `INTERNAL_SERVICE_TOKEN` — случайная строка (иначе фоновая проверка вебхука бота
  показывается как предупреждение).
- [ ] Google Analytics: Measurement ID в Admin → Analytics → Settings; при необходимости —
  доступ к отчётам (`GA_OAUTH_*`).
- [ ] Валюты и курсы: Admin → Currencies & FX.
- [ ] Приглашения оставить отзыв (`REVIEW_INVITES_ENABLED`) — включать только после SPF/DKIM и
  пары недель нормальной доставки писем.
- [ ] Мониторинг доступности снаружи (UptimeRobot, Better Stack…) на `https://<домен>/api/health`.
- [ ] **Cloudflare перед сервером** (бесплатный тариф): защита от массовых атак и кэш картинок и видео.
  Перед включением проксирования — настоящий адрес посетителя в nginx (deploy.md → «Защита от
  перегрузки»), иначе лимиты частоты станут общими на всех.
- [ ] **DLC:** на стенде заведены DLC только игр от «A» до «D» (~1 100, с трейлерами). На сервере —
  решить заново: `import-dlc all` без `--with-trailers` (~6 ГБ) или только крупные (`--min-price 10`).

## Уже сделано в коде

Для справки, чтобы не проверять повторно:

- Keycloak — боевой режим на Postgres, тот же домен под `/auth`, консоль снаружи закрыта.
- https с HSTS, редирект с http, сертификат продлевается сам.
- Mongo с паролями; у приложения права только на свою базу.
- Ротация логов всех контейнеров (10 МБ × 5).
- Лимиты чата поддержки: сессии и сообщения на IP, длина сообщений, дневной бюджет.
- Лимиты частоты в nginx по адресу (API, формы, вход, трейлеры) и тихий повтор на витрине; лимиты
  памяти контейнеров в продакшене (deploy.md → «Защита от перегрузки»).
- Медиа игр (скриншоты, трейлеры) — на своём сервере, ссылок на Steam нет.
- SMTP с логином и STARTTLS; неверные настройки почты не дают бэкенду стартовать.

# Резервные копии и восстановление

## Что копируется

Раз в сутки в `BACKUP_HOUR` (UTC, по умолчанию 3:00) в каталог `BACKUP_DIR` на сервере
(по умолчанию `./backups` рядом с compose-файлами):

| Файл | Что внутри | Хранится |
|---|---|---|
| `mongo-<дата>.archive.gz` | база магазина: каталог, заказы, ключи, пользователи сайта, настройки | `BACKUP_KEEP` (14) |
| `uploads-<дата>.tar.gz` | загруженные файлы: обложки, аватары, медиатека (без медиа игр из Steam — см. ниже) | `BACKUP_UPLOADS_KEEP` (7) |
| `keycloak-<дата>.dump` | база Keycloak: учётки покупателей, пароли, 2FA, настройки входа | `BACKUP_KEEP` (14) |

Делают это сервисы `mongo-backup` и `keycloak-db-backup` из `docker-compose.prod.yml`. Если сервер
был выключен в нужный час, копия делается при первой возможности после него. Перед каждым
`deploy/update.sh` и `deploy/restore.sh` делается внеочередная копия.

Сделать копию прямо сейчас:

```bash
docker compose exec mongo-backup bash /scripts/mongo-backup.sh --now
docker compose exec keycloak-db-backup sh /scripts/keycloak-backup.sh --now
```

Проверить, что копии идут: `ls -lh backups/` и `docker compose logs mongo-backup keycloak-db-backup`.

## Копия вне сервера

Копии на том же диске не спасут, если умрёт сервер или провайдер. Сервис `backup-offsite`
раз в сутки (через час после копий) синхронизирует каталог с внешним хранилищем через rclone.

1. Создайте бакет в любом хранилище, которое понимает rclone: Backblaze B2, S3, Яндекс Object
   Storage, Google Drive и т.п. Ключ доступа — только к этому бакету.
2. Создайте конфиг на своей машине (`rclone config`) и положите его на сервер в
   `deploy/rclone/rclone.conf` (в git он не попадает), `chmod 600`.
3. В `.env`:
   ```
   COMPOSE_PROFILES=offsite
   RCLONE_REMOTE=b2:taleshop-backups
   ```
4. `docker compose up -d`, проверка сразу: `docker compose exec backup-offsite sh /scripts/offsite.sh --now`.

`rclone sync` делает хранилище точной копией каталога: старые копии удаляются и там. Если нужна
защита от удаления (например, от злоумышленника на сервере) — включите в бакете версионирование
или object lock.

### Медиа игр из Steam

Скриншоты, трейлеры и картинки описаний игр и DLC (`/uploads/steam`, ~41 ГБ) в ежедневные копии не входят:
семь копий заняли бы 150 ГБ, а скачать их заново можно в любой момент. После восстановления на
новый сервер (или если том uploads потерян):

```bash
docker compose run -d --name steam-refresh --no-deps backend import-steam starter --update
# после него — DLC:
docker compose run -d --name dlc-refresh --no-deps backend import-dlc all --with-trailers --update
```

Импорт перечитает карточки из Steam и скачает медиа заново, цены и настройки магазина не тронет.

## Восстановление

Восстанавливает `deploy/restore.sh`. Он спрашивает подтверждение, перед заменой базы делает копию
её текущего состояния (на случай, если выбран не тот файл) и на время останавливает сервисы,
которые с ней работают.

```bash
bash deploy/restore.sh mongo    backups/mongo-20261001-030000.archive.gz
bash deploy/restore.sh keycloak backups/keycloak-20261001-030000.dump
bash deploy/restore.sh uploads  backups/uploads-20261001-030000.tar.gz
```

- **mongo** — коллекции из копии заменяют текущие целиком. Коллекции, которых в копии нет
  (появились позже), остаются как есть.
- **keycloak** — база Keycloak пересоздаётся из копии. Пользователи, зарегистрированные после
  копии, пропадут; их заказы в базе магазина останутся, но привязаны к учётке, которой больше нет.
  Поэтому после аварии восстанавливают обе базы из копий одного дня.
- **uploads** — каталог загрузок очищается и заполняется из архива.

Все три вида проверены прогоном на тестовом стеке (`down -v`, затем копия → порча → восстановление).
Проверяйте восстановление сами раз в несколько месяцев: копия, из которой ни разу не
восстанавливали, — это надежда, а не копия.

## Сервер погиб целиком

1. Новый сервер по [deploy.md](deploy.md), шаги 1–3 (тот же `.env` — его копию храните отдельно,
   например в менеджере паролей).
2. `docker compose up -d` — поднимутся пустые базы.
3. Скопировать файлы копий с внешнего хранилища: `rclone copy b2:taleshop-backups ./backups`.
4. Восстановить все три вида из копий одного дня (команды выше).
5. Сертификат — `bash deploy/issue-cert.sh`.

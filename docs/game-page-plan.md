# Страница игры — план переработки

Ветка: `feature/game-details-redesign` (от `feature/admin-panel-rework` после её коммита).
Исходник: `tale-gameshop/src/pages/game-details-page/GameDetailsPage.tsx` (+ css),
API: `GET /api/games/{slug}?currency=` (`GamesDetailsController`).

## Решения (согласованы)

1. Главное на странице — покупка: цена, тип ключа (где активировать), регион, наличие, издание.
   Хиро: галерея слева; справа название/бейджи/платформы и крупная карточка покупки с выбором издания внутри.
2. Издания — варианты одной игры (Standard/Deluxe/Ultimate), каждое со своим ключом. Нужна сквозная
   поддержка: корзина/заказ/выдача ключей по `gameId + editionCode`. Одно издание — покупатель его не видит.
3. DLC — отдельные товары (свои карточки, ведут на свою страницу), на странице игры — блок «DLC к этой игре»,
   на странице DLC — ссылка «требуется базовая игра» (как в Steam).
4. Нет данных — нет блока (где допустимо). В админке: предупреждения о неполноте карточки
   (нет трейлера / сисреков / описания / языков / возрастного рейтинга / изданий без цены) — при сохранении и в списке.
5. Медиа — одна галерея: трейлер первым (если есть), дальше картинки и доп. видео в порядке загрузки.
   Отдельный блок «Gameplay & trailer» убираем.
6. Под хиро — вкладки `Overview | Reviews | Q&A | System requirements`, отзывы и вопросы грузятся по переходу;
   `?tab=reviews` — прямая ссылка.
7. Регионы активации — сквозная фича (отдельный этап). У ключа не один регион, а **политика**:
   - `Global` — работает везде, **кроме** списка исключений (например RU, BY, CN);
   - `Regions` — набор регионов, где работает (EU, NA, CIS, TR, LATAM…), и тоже с исключениями стран.
   Регион — именованный набор стран, справочник ведётся в настройках. Покупателя определяем по стране
   (IP/таймзона + переключатель в шапке), проверка: страна ∈ разрешённым регионам и ∉ исключениям.
   Витрина: «Активируется: EU, NA · не работает в RU, CN» + предупреждение/блокировка; чекаут — проверка;
   выдача — ключ, подходящий стране покупателя; админка — остатки по политикам.
8. Наличие: «В наличии / Скоро закончится / Нет в наличии». «Скоро закончится» — по порогу
   (глобальный дефолт в настройках сайта + переопределение у игры) и/или с даты, заданной в админке.
9. «Похожие» — общий `RecommendationsSection` с главной.

## Что уже есть в данных, но не показывается

`KeyType`, `isComingSoon`/`releaseDate` (только в кнопке), остаток ключей (`CountAvailableByGameAsync`),
срок скидки (`GameDiscount.endDate`), `Awards` (список), `Languages.Audio`, `AgeRating.IconUrl`,
`Developer/Publisher.Website`, `userContext.hasPurchased/myReview/isWishlisted`, shop reply / official answer
(без выделения), способы оплаты (`StorefrontPaymentMethods`), промокоды, `editionPricing` (не доходит до корзины).

## Этапы

### A. Каркас, хиро, покупка (витрина)
- Одни крошки (+ `BreadcrumbList` JSON-LD), скелет загрузки вместо «Loading…».
- Хиро: галерея (трейлер → картинки → видео), справа: название, тэглайн, бейджи (скидка, новинка, top, Steam/Epic…),
  платформы svg-иконками, жанры/тэги ссылками в каталог.
- Карточка покупки: цена/старая цена/скидка **и до какого числа**, выбор издания (если >1), тип ключа +
  ссылка «как активировать» (support docs), наличие (3 состояния), способы оплаты (иконки включённых рейлов),
  «Instant delivery / Refund policy» ссылками, Add to cart / Wishlist; coming soon — как сейчас.
- В корзину уходит издание (`editionCode`, цена издания) — пока фронтово, бэкенд в этапе D.
- «Not available in EUR» — не экран-заглушка, а страница с пометкой и ценой в базовой валюте без кнопки покупки.

### B. Контент
- About: markdown, key features, awards списком (год/тип/иконка).
- Таблица языков: язык | интерфейс | озвучка (из `Languages.Text/Audio`).
- Сисреки: переключатели Windows/Mac/Linux и Minimum/Recommended, пустые поля не рендерим.
- Developer/Publisher: ссылка на сайт + «ещё игры студии» → каталог с фильтром.
- Блоки без данных не рендерятся; пустые «Edition/DLC/Game details» уходят.

### C. Отзывы и Q&A (вкладки)
- Компактные фильтры, убрать фейковую сортировку «Verified purchases» (сделать фильтром), человеческие даты,
  аватары-заглушки с инициалами, «Read more» только для длинных.
- Сводка: средняя, распределение, % рекомендуют.
- Мой отзыв сверху; форма — только для купивших (`userContext.hasPurchased`), иначе подсказка.
- Ответ магазина / официальный ответ выделены.
- Q&A: вопросы с официальными ответами первыми, «задать вопрос» — для авторизованных.

### D. Бэкенд под витрину
- В ответ details: `availability` (inStock/lowStock/outOfStock, с учётом порога и даты), `discountEndsAt`,
  `keyType` уже есть, `paymentMethods` (или отдельный запрос), `editions` с доступностью по ключам.
- Издания сквозь корзину → заказ → выдача ключей (`GameKey.EditionCode`, импорт с выбором издания, остатки по изданиям).
- DLC как товары: `Game.ParentGameId`/`IsDlc`, каталог, страница DLC, блок на странице базовой игры.
- Настройки: глобальный порог «скоро закончится», у игры — порог и дата показа.
- Админка: предупреждения о неполноте карточки (список игр + при сохранении).

### E. Регионы активации (сквозной этап)
- Справочник: страны (ISO-3166) и регионы как наборы стран — в настройках сайта, с дефолтным набором (Global, EU, NA, CIS, TR, LATAM, ASIA).
- `KeyRegionPolicy { Mode: Global|Regions, Regions: [..], ExcludedCountries: [..] }` — у ключа (при импорте)
  и дефолтная у игры/издания (чтобы не задавать каждому ключу); ключ без политики наследует её от игры.
- Страна покупателя: определение (IP через заголовок от nginx/CDN, иначе таймзона) + переключатель в шапке + cookie.
- Витрина: «Активируется: …», «Не работает в: …», предупреждение, если страна покупателя не подходит, кнопка покупки
  выключена с пояснением (или «уведомить, когда появится»).
- Чекаут: проверка страны против политик доступных ключей; фулфилмент: выдача ключа, подходящего стране;
  если подходящего нет — не выдавать «любой», а эскалировать (как при нехватке).
- Админка: импорт ключей с политикой, остатки в разрезе политик, низкий остаток по региону, предупреждение у игры
  «нет ключей для популярных регионов».

### F. Рекомендации, SEO, аналитика
- `RecommendationsSection` вместо самописной карусели.
- `BreadcrumbList`, нормальное `description`; событие «add to cart со страницы игры» в аналитику.

## Открытые вопросы
- Регионы покупателя: по IP (нужен геосервис/заголовок от nginx/CDN) или только таймзона + ручной выбор?
- DLC: выдача ключа DLC — тот же пул ключей с привязкой к DLC-товару (наиболее просто).
- Нужно ли «уведомить о поступлении» для «Нет в наличии» (у нас есть newsletter/почта)?

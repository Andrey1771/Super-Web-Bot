# Демо-сайт для портфолио

Отдельная установка магазина, которую можно дать «потрогать» клиентам. Работает как обычный магазин — посетители
регистрируются, покупают тестовой картой и пишут в поддержку, — а админку показывает общий демо-админ, который
ничего не может испортить.

## Как устроено

- **Обычный магазин.** Посетитель создаёт свой аккаунт (регистрация открыта; почту нужно подтвердить — письмо уходит
  сразу при регистрации, ссылка живёт сутки),
  покупает любую игру тестовой картой и получает ключ на странице заказа и письмом. Чат с ботом поддержки открыт всем.
  Код: `SuperBot.WebApi/Demo`, фронт — `tale-gameshop/src/features/demo`.
- **Демо-админ — только просмотр.** `demo-admin` с публичным паролем видит всю админку, но любые изменения
  (товары, цены, настройки, рассылки, свой пароль и профиль, карты) получают отказ `demo_readonly` (`DemoGuard`,
  `DemoGuardMiddleware`). Купить он может: корзина, промокод, оплата тестовой картой (новые карты на кассе не
  сохраняются — список общий) и показ своих ключей; повторной отправки ключей письмом нет — адрес у него `.invalid`.
  На такие адреса (`.invalid`, `.test`, `example.com`…) почта не отправляет вообще (`SmtpMailSender.IsUndeliverable`). Почты посетителей в ответах ему маскируются: `j***@gmail.com` — посетители
  регистрируются своими настоящими адресами; IP и устройства (активные сеансы, история входов, заявки на
  восстановление) скрыты прямо в ответах сервера, а не только на экране. Страницы аккаунта Keycloak у него нет
  (ни одной роли клиента account): даже просмотр отдавал бы сеансы с IP всех, кто входил под общей учёткой.
- **Почта настоящая**: письма с ключами, «Забыли пароль?», уведомления — через SMTP из `.env`
  (Resend, приём — Cloudflare Email Routing; см. «Почта» ниже).
- **Оплата** — Stripe в тестовом режиме: карта `4242 4242 4242 4242`, любой срок и CVC. Подсказка с картой — в окне
  приглашения, в кружке «Демо» и на кассе.
- **Демо-ключи** `DEMO-XXXXX-XXXXX-XXXXX` — по 25 на товар и издание, с закупочной ценой (оживают отчёты).
  Раз в час доливаются до 25 (`DemoKeyTopUpWorker`): покупки посетителей не распродают каталог.
- **Telegram Stars в демо выключены** (`DemoBotGuard`).
- **Поисковикам закрыт**: robots.txt «Disallow: /» и заголовок `X-Robots-Tag: noindex`.
- **Админ-консоль Keycloak снаружи закрыта**, как в продакшене: `/auth/admin/` и `/auth/realms/master/` отвечают 404
  (`nginx/docker-entrypoint.d/35-taleshop-demo.sh`). Владельцу — через SSH-туннель:
  `ssh -L 8088:127.0.0.1:8088 сервер` → `http://localhost:8088/auth/admin`. Ссылок на консоль (Roles, Sessions,
  Keycloak console) в меню админки здесь нет — без туннеля они никуда не ведут; на стенде разработчика они остаются.

## Каталог демо

`deploy/demo/catalog.json` — 70 узнаваемых игр по всем категориям, 110 DLC (у Batman: Arkham Knight и
Cities: Skylines II — все, у остальных до пяти самых дорогих, без роликов) и 5 программ из Steam. Пакет собирается
на стенде разработчика из его базы и медиа:

```bash
bash deploy/demo/build-demo-pack.sh            # → demo-pack/db.archive.gz (~1 МБ) и uploads.tar (~3,8 ГБ)
```

База стенда не меняется: пакет собирается в отдельной базе `TaleShopDemo`.

## Установка на сервер

Сервер может быть общим с другими сайтами: демо слушает только `127.0.0.1:8081`, а 80/443 держит системный
nginx сервера. Памяти нужно от 2 ГБ **и swap** (лимиты контейнеров — в `docker-compose.demo.yml`), диска — около 10 ГБ.

1. **Swap**, если его нет (2 ГБ):
   ```bash
   sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
   echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
   ```
2. **Код и `.env`** — как в [deploy.md](deploy.md) (шаги 1–3), плюс:
   ```bash
   COMPOSE_FILE=docker-compose.yml:docker-compose.prod.yml:docker-compose.demo.yml
   MONGO_DB=TaleShopDemo
   DEMO_ADMIN_PASSWORD=…        # публичный: его видят посетители демо
   STRIPE_SECRET_KEY=sk_test_…  # только тестовые ключи
   STRIPE_PUBLISHABLE_KEY=pk_test_…
   ```
   Почта — см. «Почта через Cloudflare» ниже. `BOT_TOKEN` — только отдельного демо-бота (не рабочего), или пусто.
3. **Запуск:** `docker compose up -d`.
4. **Каталог:** скопировать пакет на сервер и развернуть:
   ```bash
   scp -r demo-pack сервер:/opt/taleshop/          # с машины, где собран пакет
   bash deploy/demo/restore-demo-pack.sh demo-pack # на сервере
   ```
5. **Keycloak:** `bash deploy/demo/keycloak-demo-users.sh` (демо-админ, открытая регистрация),
   `bash deploy/keycloak-smtp.sh` (почта Keycloak) и `bash deploy/demo/keycloak-demo-guard.sh --install` — сторож
   демо-админа в cron: раз в минуту убирает у общей учётки 2FA, резервные коды и ключи доступа и возвращает
   публичный пароль, если его сменили (настройка 2FA открывается ссылкой Keycloak в обход кнопок сайта). Журнал —
   `/var/log/taleshop-demo-guard.log`, пишет только когда что-то откатил.
6. **Системный nginx и сертификат** — по шагам в `deploy/demo/host-nginx.conf`.
7. **Stripe (тестовый режим):** вебхук `https://<домен>/api/payments/webhook` с событиями из deploy.md, его
   секрет — в `STRIPE_WEBHOOK_SECRET`.

Обновить каталог — собрать пакет заново и повторить шаг 4. **Заказы, чаты и отзывы посетителей при этом стираются**
(они в той же базе); аккаунты в Keycloak остаются.

## Наполнение: история заказов, отзывы, распродажи

Чтобы админка и кабинет демо-админа не были пустыми, после установки:

```bash
docker compose run --rm --no-deps -e Mail__DryRun=true backend demo-seed demo-admin@taleshop-demo.invalid 60 120
```

60 заказов за последние 120 дней (каждый седьмой — у демо-админа, с кэшбэком), два возврата (полный и по позиции),
отзывы, 8 распродаж и промокоды SPRING15 / GAMER5 / VIP25 / STEAMFEST10 (истёк) / WEEKEND20 (ещё не начался).
Заказы оформляются настоящими тестовыми платежами Stripe (нужен `sk_test_` — с живым ключом команда откажется)
и штатной финализацией, потом их даты переносятся в прошлое. Покупатели выдуманные (`@example.com`), письма
не отправляются (`Mail__DryRun`). Повторно без `--force` не запускается; `--orders-only` — пробный прогон.

### Второй слой: статистика во всех разделах админки

```bash
bash deploy/demo/fill-demo.sh 180 60     # заказов, дней (не больше 80: события воронки живут 90 дней)
bash deploy/demo/fill-demo.sh --reset    # убрать наполненное (кроме заказов) и учётки покупателей
```

40 зарегистрированных покупателей в Keycloak (@example.com, случайные пароли, разные даты регистрации) и 12 гостей;
заказы — тестовыми платежами Stripe, с каналами (google/cpc, reddit, youtube, newsletter…), странами и промокодами;
воронка «просмотр → корзина → оформление → покупка» связана с заказами; брошенные корзины, подписчики и 4 рассылки,
64 чата с ботом (часть — у специалиста), 8 обращений, 5 отзывов на модерации, 3 неудачных платежа, недельные расходы
на рекламу. Блог: `seeds/seed-engagement.js` (имя базы в нём — базы разработки; на демо подставить `TaleShopDemo`,
запуск с `ALLOW_DEMO_SEED=1`). Что записано, перечислено в коллекции `DemoFill`.

Сохранённые карты демо-админа (Billing): `bash deploy/demo/demo-admin-cards.sh` — Visa 4242 (основная), Mastercard 4444
и Visa 3155 (3-D Secure) привязываются через тестовый Stripe от имени сервера; повторный запуск карты не дублирует.

## Почта

**Отправка — Resend** (бесплатно 3000 писем в месяц, 100 в день; для демо с запасом):

1. resend.com → **Domains → Add Domain** → домен сайта, регион Ireland. DNS-записи (DKIM `resend._domainkey`, MX и SPF
   поддомена `send`) — в Cloudflare, кнопкой автонастройки или вручную; дождаться **Verified**.
2. **API Keys → Create API Key** (Sending access, этот домен) — ключ `re_…` показывается один раз.
3. На сервере: `bash deploy/set-smtp.sh` (спросит ключ, не показывая его; с компьютера —
   `ssh -t … bash /opt/taleshop/deploy/set-smtp.sh`, без кавычек — их портит PowerShell; не в PowerShell ISE).
   Ставит SMTP_* на smtp.resend.com:465, логин `resend`, отправитель `no-reply@<домен>`, старый `.env` — копией.
4. `docker compose up -d --no-deps --force-recreate backend` и `bash deploy/keycloak-smtp.sh` («Забыли пароль?», 2FA).

Другой сервис — те же шаги: `SMTP_HOST=… SMTP_PORT=… SMTP_USERNAME=… MAIL_FROM=… bash deploy/set-smtp.sh`
(например, Cloudflare Email Sending: smtp.mx.cloudflare.net:465, логин `api_token`, нужен тариф Workers Paid).

**Приём — Cloudflare Email Routing** (бесплатно): Email → Email Routing → включить для домена, Destination address
(подтвердить письмом), правило `support@<домен>` → этот ящик. Адрес поддержки сайта — в настройках (Settings.SupportEmail)
и `Legal__SupportEmail` в `docker-compose.demo.yml`. Проверять письмом с другого ящика: Gmail не показывает во «Входящих»
письмо, вернувшееся к отправителю пересылкой.

## Если что-то пошло не так

- Демо-админ заблокирован перебором паролей — Keycloak снимает блокировку сам через 15 минут.
- Письма не уходят — `docker compose logs backend | grep -i mail`; ответ `550 5.7.1` — домен в `MAIL_FROM`
  не включён в Email Sending или токен от другого аккаунта.
- Даты «скоро выйдет» — настоящие даты релизов: со временем такие игры просто выходят. Обновить — пересобрать пакет.
